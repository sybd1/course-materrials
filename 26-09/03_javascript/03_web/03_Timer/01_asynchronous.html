비동기(Asynchronous) 프로그래밍

1. '동기' 식당의 문제점: 블로킹(Blocking)

    '동기' 처리는 앞선 작업이 끝날 때까지 다음 작업이 하염없이 기다리는 방식입니다.
    웹 페이지에서 시간이 오래 걸리는 작업을 동기 방식으로 처리하면, 페이지 전체가 '얼음'처럼 멈춰버립니다.

2. '비동기' 식당의 해결책: 타이머 함수

    `setTimeout`과 `setInterval`은 대표적인 비동기 함수입니다.
    '나중에 할 일'을 브라우저에게 맡겨두고, 자신은 즉시 다음 코드를 실행하여 멈춤 현상을 막습니다.

setTimeout: "조금 이따가, 딱 한 번만 해줘!"

3. 비동기는 어떻게 동작할까? (이벤트 루프)

    자바스크립트 요리사(JS 엔진)는 한 번에 한 가지 일만 할 수 있는 '싱글 스레드'입니다.
    하지만 주방 보조(브라우저)는 타이머, 네트워크 요청 등 여러 일을 동시에 할 수 있는 '멀티 스레드'이죠.

    비동기 처리 과정은 다음과 같습니다.
    1. Call Stack (메인 주방): JavaScript 엔진이 지금 실행 중인 작업 공간
    2. Web API (주방 보조): 브라우저가 제공하는 타이머, 이벤트, 네트워크 처리 공간
    3. Task Queue (주문서 목록): 비동기 작업이 끝난 뒤 실행 대기 중인 콜백들이 줄 서는 공간
    4. Event Loop (주방 매니저): Call Stack이 비었는지 확인하고, Queue의 콜백이 다시 Stack으로 올려주는 관리자
