- Overloading: 매개변수가 있는 생성자의 매개변수 값이나 자료형이 다르면, 같은 메서드 이름을 사용할 수 있는 규칙. 이름은 같지만 시그니처가 다른 메서드를 여러 개 정의하는 기술

메서드 시그니처: 메서드를 식별하는 고유한 바코드. 메서드 이름 + 매개타입 변수, 개수, 순서

성립하는 경우: 타입이 다를 때도 성립, 매개변수의 갯수가 달라도 성립.

불성립하는 경우: 반환 타입만 다른 경우, 접근 제한자만 다른 경우, 매개변수 이름만 다른 경우.

overloading을 사용하지 않으면 조건이 변경 될 때마다 새로운 클래스나 메서드를 만들어야 한다.

같은 메서드 이름으로 다양한 메서드를 사용할 수 있다.

- 파라미터(매개변수)를 넘겨줄 때 벌어지는 일
값이 복사되는 방식(Pass by Value)과 주소가 복사되는 방식(Pass by Reference) 2가지가 있다.

Pass by Value: 값을 복사해서 전달하면, 전달받은 메서드에서 값을 바꾸더라도 원래 변수에는 영향을 주지 않는다. 값 자체만 복사를 한다.
Pass by Reference: 배열이나 객체는 가리키는 참조값이 복사된다. 같은 객체의 내부 데이터를 바꿀 수 있다. 원본이 바뀐다. 

“객체의 내부 데이터를 바꾸는 것”과 “변수가 가리키는 대상을 바꾸는 것”은 서로 다른 작업

참조값을 복사해서 원본 데이터가 바뀌는 것은 깊은 복사가 아니라, 같은 객체를 공유하기 때문에 발생하는 현상

- 싱글톤 패턴
singleton = static + private 생성자
Spring Boot 프레임워크에서는 @Service @Repository로 간단하게 싱글톤을 만들어 관리할 수 있다.
프로그램 전체에서 특정 클래스의 인스턴스(객체)가 단 하나만 존재하도록 보장한다. (DB 연결 설정, 로그 시스템, 앱 전역 설정값... 등등)

1. 생성자 private -> 외부에서 new로 객체를 못 만들게 함.
2. private static 필드 -> 클래스 스스로 자기 객체를 딱 하나 만들어 보관
3. public static 메서드 -> 그 하나의 객체를 외부에 건네주는 창구를 만듦

이른 초기화: 클래스가 초기화될 때 인스턴스를 미리 생성.
게으른 초기화: 실제로 필요해질 때 인스턴스를 생성.



- 지역변수, 인스턴스 변수, 클래스 변수
지역변수: Stack에 저장된다. 메서드 안에 선언하는 변수. 메서드가 호출 될 때 Stack 메모리에 생성되었다가 }를 만나는 순간 즉시 사라진다. 기본값이 없기 때문에 초기화 하지 않으면 사용 불가능하다. JS는 이런 경우 유연하게 Undefined 값을 출력하지만, Java에서는 불가능하다. 메서드 내에서 생성됐다가 사라지기 때문에, 다른 메서드 블럭에서는 아예 불러올 수 없는 존재하지 않는 값이다.

인스턴스 변수: Heap에 저장된다. new실행시 생성.

클래스 변수: Static에 저장된다. 프로그램 시작 시 생성.




- 객체 배열
기본 자료형 외 사용자 정의형 자료형을 따로 만들어서 사용하던 것처럼 배열의 자료형도 사용자 정의형으로 만들어서 사용할 수 있다. 사용자가 정의한 배열의 기본값은 null이다. 객체 배열도 선언과 동시에 객체 배열 초기화가 가능하다.
