1. Exception
크게 unchecked 와 checked 두 개로 나뉜다.
Exception도 거대한 클래스이다. Exception에 포함된 알맞은 클래스를 사용해서 예외처리를 해준다.

Checked Exception: 컴파일러가 처리 또는 throws 선언을 확인한다.
UnChecked Exception: 컴파일러가 처리를 강제하지 않으며 주로 실행 중 발견된다. 
runtime 시점에 발생하는 에러. compiler가 발견하지 못하기 때문에 runtime을 하기 전에 예외처리를 해준다.

예외처리를 하려고 하는 메서드는 alt + Enter 하면 자동으로 try/catch문으로 닫아준다.

printStackTrace(): 학습이나 개발 중에 예외가 발생했을 때 추적할 수 있는 메서드. 실제 서비스에서는 보통 로깅 도구를 이용하여 필요한 정보를 기록한다.

NoSuchElementException: 요소를 찾을 수 없습니다.

메서드 시그니처: 메서드를 구분하는 이름과 매개변수 목록. 메서드 식별 목록. 메서드 시그니처는 특정 위치를 뜻하는 게 아니라, 메서드를 식별하는 정보를 뜻.

Exception을 상속받은 자식 클래스는 Exception 클래스 내의 기능을 자동으로 사용할 수 있게 된다.



Q. 자식 메서드가 부모보다 더 넓은 익셉션을 오버라이딩해서 throws 해도 되는가?

IOException : 입출력(I/O) 작업 도중 예기치 못한 문제가 발생했을 때 던지는 대표적인 예외(Exception) 클래스???

부모가 Exception을 메서드에 넣어도, 자식이 오버라이딩했을 때 Exception 구문을 사용하지 않아도 된다.

자식 클래스에서 부모가 준 IOException 하위 예외처리 클래스를 사용해도 괜찮은가?
괜찮다.

선언하지 않아도, 같은 범위여도, 부모보다 더 구체적인 범위도 허용한다.

자식 메서드가 부모 메서드 보다 더 넓은 범위의 예외처리를 불가능하다. 계약이 깨진다.

throw: 예외를 강제로 발생시킨다. 메서드 내부에서 사용한다. 조건에 맞지 않을 때 직접 예외 객체를 생성해서 던지는(발생시키는) 역할.
throws: 예외를 상위 호출자로 떠넘기기 / 전가하기. 메서드 선언부(이름 뒤, 소괄호와 중괄호 사이)에 사용.

- Stream
파일과 프로그램을 왔다 갔다 이동해주게 하는 기능. input, output은 프로그램 기준으로 생각해야한다.

- byte 단위 input Stream
FileInputStream 클래스: 파일의 데이터를 바이트 단위로 읽는 입력 스트림. 이미지, 영상, 텍스트 등 모든 파일은 바이트로 읽을 수 있다. 다만 텍스트를 한글 같은(유니코드) 문자로 처리할 때는 Reader 계열을 사용하는 편이 알맞다.
유니코드(텍스트)를 그대로 올바르게 읽지 못하기 때문이다.
아스키 코드만 읽을 수 있는 것이 아니라, 글자(텍스트/유니코드)를 읽을 때는 바이트 단위로 무식하게 쪼개버리기 때문에 글자가 깨지는 것뿐이다.

(FileInputStream e)
e.read(): 파일에 기록된 값을 1바이트씩 읽어온다. 더 이상 읽을 데이터가 없으면 -1을 반환. 아스키 코드로 반환.

사용이 끝난 스트림은 반드시 닫아준다 (자원 반납)
close() 메서드로 닫을 수 있다.


try-with-resources 구문
자동으로 close()를 호출해주는 문법.


- byte 단위 output Stream
FileOutputStream 클래스: 데이터를 1바이트씩 파일에 출력하는 스트림

(FileOutputStream e)
e.write(): 소괄호에 아스키 코드를 넣으면 파일 안에 값을 입력할 수 있다.

byte 배열을 이용하여 여러 바이트를 한 번에 기록
byte[] bar = new byte[] {98, 99, 100, 101, 10};
e.write(bar);

지정된 파일의 값을 변경해도, FileOutputStream를 사용하면 기본적으로 값을 수정된 값을 지우고 덮어쓴다.
이어쓰기가 필요하다면 new FileOutputStream(path, true)처럼 append 옵션을 선택해야 한다.

- BufferedWriter / BufferedReader
BufferedWriter
버퍼는 데이터를 모아두는 공간. 데이터를 바로바로 파일에 쓰거나 읽는 것보다, 버퍼를 거치면 파일에 직접 연결되어 주고받는 입출력 횟수를 줄일 수 있다.
기본 스트림(FileWriter / FileReader)을 감싸서 사용하는 보조 스트림

한글자씩 입출력을 하는 것이 아니라, 버퍼에 모아둔 값을 한번에 효율적으로 처리한다.

try-with-resources 구문을 사용하면 close()가 자동으로 이 기능을 해주는데 close() 메서드에 flush()메서드가 포함되어 있어서 편리하게 사용할 수 있다.

enum으로 만든 클래스에 들어있는 값들은 고유한 상수이다.

클래스를 enum으로 선언하면 그 클래스는 하나의 타입이 된다.

.ordinal(): 현재 상수의 선언 위치를 0부터 반환
name(): 같은 상수의 소스 이름을 문자열로 반환

enum 상수 하나하나 설명을 추가할 수 있다.
enum안의 값 상수들은 하나의 객체이다. 값을 넣으면 상수이기 때문에 생성자를 호출하여 초기화를 바로 해야한다.
