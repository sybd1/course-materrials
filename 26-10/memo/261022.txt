카디널리티: 튜플의 수. 그리고 데이터 모델링의 관계에서는 카디널리티를 1:1, 1:N, M:N 같은 관계의 수적 대응으로도 사용해. 문맥을 구분해서 사용.
엔티티와 엔티티 사이의 관계의 개수

- 논리 모델
개념 모델을 상세화하는 작업. 정규화를 진행하는 단계. MySQL을 사용하기 전이다. DBMS가 달라져도 논리 모델은 유지되어야 한다.
업무 요건을 빠짐없이 반영해야한다. 더 이상 추가할 엔티티가 없는지 식별자 형태를 어떻게 할지 마무리 해야 한다.

원자성 Atomicity
원자값이란 해당 속성의 값이 그 모델에서 하나의 값으로 취급된다는 뜻.

함수 종속
X → Y는 X의 값이 정해지면 Y의 값이 하나로 결정
릴레이션 내에 존재하는 속성 간의 종속성을 의미한다.

원자성: 한 속성에 어떤 형태의 값을 저장하는가?
함수 종속: 한 속성의 값이 다른 속성의 값을 결정하는가?

정규화 (Normalization): 데이터베이스에서 데이터를 여러 테이블로 적절하게 분리하고, 테이블 간의 관계를 설정해 데이터 중복과 데이터 변경 시 발생하는 문제를 줄이는 과정.


정규형은 제1정규형~제5정규형까지 과정이 있다. 보통은 제3정규형까지 진행된다.

**다가 속성**과 관련된 1정규형 처리 방법
한 릴레이션에서 같은 속성이 늘어나면 컬럼을 늘려 추가하는 것이 아니라, 새로운 릴레이션을 만들어서 관리한다.
"취미의 개수가 2개이상 계속 늘어나면 컬럼을 그만큼 추가할 것이 아니라, 새로운 테이블로 분리해 FK로 취미만 관리하는 것이 더 효율적이다."
인조식별자를 활용하는 방법도 있다.

**복합 속성**과 관련된 1정규형 처리 방법
주소라는 속성은 여러 속성이 하나로 묶인 복합속성의 의미가 될 수 있다.

1정규화는 원자값을 지녀야 한다. 여러 행으로 분리한다.

2정규화는 복합주식별자의 경우 따로 분리해 X Y의 관계의 종속관계를 만든다.

3정규화는 이행적 종속성을 제거하고 일반 속성 간에 종속관계가 없도록 처리한다.

- 물리 모델
DBMS 결정. MySQL 정하기.
논리 모델에서는 DBMS와 상관없이 작동한다.
물리 모델은 DBMS와 실제 운영 성능을 생각하고 모델링한다.

특정 성능 문제를 해결하기 위한 목적이 아니라면 비정규화는 고려하지 않는다.

슈퍼타입과 서브타입: 엔티티안에 엔티티안에 엔티티
물리모델에서는 존재할 수 없다. IE 표기법에서는 아예 존재하지 않는다. 논리모델로 보기 편하게 Baker 표기법으로 표기하는 것이다.

뷰와 인덱스 
뷰: 하나의 테이블, 혹은 여러 테이블에 대하여 특정 사용자나 조직의 관점에서 데이터를 바라볼 수 있도록 해주는 수단으로서 가상 테이블이라고도 부른다. 복잡한 쿼리가 요구되는 것들을 접근 권한 제어를 위해 생성할 수 있다.

비정규화 Denormalization
잘못해서 비정규화를 하는 것은 아니다. 정규화가 비효율적이라고 생각할 때 선택해서 비정규화를 진행할 수 있다.
